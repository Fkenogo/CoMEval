# CoMEval agent instructions

## Product work sequence

This project is in Founder-led product definition. The Founder and product lead work through the problem, users, current process, definitions, constitution and product foundation in discussion, recording decisions in this repository as they are agreed.

Do not treat the prototype, provisional Product Foundation, or pilot acceptance proposal as approved product truth. Do not begin feature engineering, select infrastructure, or expand implementation scope before an explicit Founder-approved engineering assignment. Coding agents may be brought in to reconcile the prototype when specifically needed and for engineering later. Documentation changes that record Founder discussion are in scope when directed.

Start with the Master Programme and Problem Exploration. Keep observations, source evidence, assumptions, proposals, decisions and open questions distinguishable.

## START-01

Before any specifically authorized coding, prototype reconciliation, integration, preview or release assignment, establish the starting point before modifications. Read the Master Programme, relevant product decisions, and the exact handover. Record task authority and observation time, refreshed remote main SHA, branch/head and merge base, dirty files and worktrees, relevant PRs, accepted experience reference, task-relevant entrypoints, preview identity when relevant, unresolved conflicts and the scoped verdict. State START FROM and DO NOT START FROM. Preserve local changes and existing previews. Stop affected implementation if the accepted source or authority is unclear.

At handover record exact SHAs, PR, verification evidence, limitations, open decisions and next starting point. Keep implementation, Founder acceptance, merge and deployment states distinct.

## Use of project materials

The two design-partner projects have separate owners and access boundaries. Keep each project’s materials and data scoped to its authorized project. Use fictional fixtures in public-repository code, branches, PRs and tests. Do not add client source links, project-specific configurations, evidence, participant information or credentials to this public repository.
