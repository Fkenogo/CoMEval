# CoMEval — Design Partners and Pilot Proposal

**Status:** Provisional discussion input. Pilot and engineering scope not approved.  
**Updated:** 22 November 2026

Both project owners are expected design partners and anticipate the solution. Each owner should access their own project. This establishes the two use cases informing product definition. It does not yet settle each owner's validation role, operating permissions, project data use, or pilot commitments.

## Use cases

| Use case | Context to understand | Questions for product definition |
| --- | --- | --- |
| ChildFund livelihoods evaluation | Baseline-to-endline evaluation; household and youth measures; implementation and evaluation material | How are delivery records connected to measured change? Which people, locations, periods and sources must remain traceable? |
| Omugo multisector project | Multiple sectors and respondent groups; survey tools, periodic reporting and endline material | How do different instruments feed indicators and reports? Which measures repeat across rounds or sectors, and how are comparisons currently made? |

These contexts should test both common needs and meaningful differences. Do not assume that all sectors, respondent groups, indicators or project owners use the same workflow.

## Later pilot planning

The earlier proposal for a two-configuration field-to-report engineering slice remains an idea for later review. Revisit it only after the problem, users, current work, definitions, CoMEval Constitution and product foundation are agreed. Pilot planning should then specify each owner’s participation, access, data and evidence permissions, reporting cycle, support expectations and success measures.
